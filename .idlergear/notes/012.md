FAISS optimization opportunities for Klareco retrieval

## Current Implementation Analysis

**FAISSSlotRetriever (slot_retriever_faiss.py:116-117)**:
- Uses `IndexIVFFlat` for >10K docs
- nlist = √N (e.g., 2,056 clusters for 4.2M docs)
- nprobe = min(32, nlist) - hardcoded at search time
- IndexFlatIP for <10K docs
- No Product Quantization (stores full vectors)
- No HNSW optimization
- No GPU acceleration

## FAISS Documentation Insights

**7 major optimization opportunities identified:**

1. **HNSW for better accuracy/speed** (Guidelines recommend for no memory pressure)
2. **Product Quantization** for memory reduction (M/2 bytes per vector with PQ_M_x4fsr)
3. **GPU acceleration** (FAISS 1.13.2 has GPU support, not used)
4. **Tunable nprobe** at runtime (currently hardcoded at 32)
5. **ID-based filtering** for structural constraints
6. **Polysemous codes** for binary pre-filtering
7. **Better nlist sizing** for 4.2M scale dataset
