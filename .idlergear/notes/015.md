Unexplored deterministic retrieval approaches for Esperanto

**What we have:** Slot-based (SUBJ/VERB/OBJ embeddings)

**Unexplored deterministic alternatives leveraging AST + regular grammar:**

1. **Grammar Token Inverted Index**
   - Canonicalizer already produces deterministic tokens: `root:hund`, `suf:et`, `ending:o`, `case:akuzativo`
   - Build inverted index: token → doc IDs (0 learned params!)
   - Query: "hundeto" → lookup [`root:hund`, `suf:et`, `ending:o`] → intersect doc sets
   - Pro: Pure symbolic, no embeddings needed
   - Con: Exact match only (no fuzzy/semantic)

2. **Morphological Expansion/Contraction**
   - Query "hundo" expands to [hund, hundo, hundoj, hundon, hundojn, hundeto, hundaro, malgranda_hundo]
   - Deterministic rules: root + all valid suffix combinations
   - Index by lemma (root only), retrieve all inflections
   - Pro: Handles Esperanto's compositional morphology perfectly
   - Con: Misses semantic similarity (hundo ≠ kato)

3. **Dependency Tree Matching**
   - AST has dependency structure (kerno + priskriboj)
   - Index: dependency triples (head_root, relation, dep_root)
   - Query: "granda hundo" → [(hund, priskriboj, grand)]
   - Match sentences with same dependency patterns
   - Pro: Captures modifier relationships
   - Con: Requires graph matching (slower)

4. **Correlative Table Lookup**
   - Parser decomposes correlatives: kiu → ki (interrogative) + u (person)
   - Index by correlative semantics: {demanda, persono} → doc IDs
   - Query "Kiu?" matches docs with {demanda, persono} or {montra, persono}
   - Pro: Leverages Esperanto's regular correlative table (0 params!)
   - Con: Limited to correlative-based queries

5. **Affix-Based Semantic Classes**
   - Index by suffix semantics: -ejo (place), -ulo (person), -ilo (tool)
   - Query "library" → match docs with [libro+ejo] pattern
   - Deterministic rules: suffix → semantic category
   - Pro: Captures compositional semantics without embeddings
   - Con: Limited to affix-expressed meanings

6. **Canonical Signature String Matching**
   - Canonicalizer produces: `SUBJ:root=hund|pos=substantivo|num=singularo`
   - Index by signature patterns with wildcards
   - Query pattern: `SUBJ:root=*|pos=substantivo|case=nominativo`
   - Pro: Grammar-aware partial matching
   - Con: No semantic similarity

7. **Fundamento Tier-Based Boosting**
   - Parser knows Fundamento roots (tier 1 vocabulary)
   - Deterministic scoring: Fundamento root match = +10, ReVo = +5, other = +1
   - Query "Esperanto fundamenta" → boost docs using Fundamento vocab
   - Pro: Leverages authoritative vocabulary (0 learned params)
   - Con: Doesn't help with OOV queries

8. **Participial Voice/Tense Alignment**
   - Parser extracts: {voĉo: "aktiva", tempo: "prezenco"} from -ant suffix
   - Index by [voice, tense] combinations
   - Query "vidanta" → match docs with active present participles
   - Pro: Leverages Esperanto's regular participial system
   - Con: Limited scope (only participles)

**Key insight:** We have a canonicalizer that's underutilized! It produces deterministic grammar tokens and signatures but we're only using learned embeddings.

**Hybrid approach:** Combine token inverted index (exact match) + slot embeddings (semantic match)
