Deep learning opportunities after M3 deterministic retrieval

**What we have so far:**
1. **Deterministic foundation** (0 params):
   - Parser: 16 Esperanto rules → AST with morphology
   - Canonicalizer: Deterministic tokens (root:hund, suf:et, case:akuzativo)
   - M3 token inverted index: Pure symbolic retrieval

2. **Minimal learned models** (733K params total):
   - CompositionalEmbedding: root (712K) + affix (21K) embeddings
   - Composition methods: sum, concat, gated, attention (currently just sum)
   
3. **AST infrastructure**:
   - EnrichedAST: Pipeline with 4 stages (only Stage 1 complete)
   - ASTToGraphConverter: Converts AST → PyG graph for GNNs
   - 10 edge types (has_subject, has_verb, modifies, etc.)

**Key insight:** We have AST-to-graph infrastructure but NO graph neural networks trained yet!

**Deep learning opportunities following "AST as thoughts":**

1. **TreeLSTM/GNN Sentence Encoder** (NEW: 2-5M params)
   - Input: AST graph with compositional embeddings
   - Architecture: Child-Sum TreeLSTM or GCN over syntax tree
   - Output: Structure-aware sentence embedding (128d)
   - **Why**: Captures syntactic dependencies (SUBJ-VERB-OBJ relations)
   - **Use**: Better sentence similarity than averaging word embeddings

2. **AST-Constrained Attention** (NEW: 1-2M params)
   - Input: Query AST + Document AST graphs
   - Architecture: Cross-attention between query/doc nodes, constrained by edge types
   - Output: Attention weights showing which AST nodes match
   - **Why**: Aligns query subjects with doc subjects, verbs with verbs
   - **Use**: Explainable matching scores ("verb matches: 0.9, subject matches: 0.7")

3. **Slot-Aware Bi-Encoder** (NEW: 5-10M params)
   - Input: SUBJ/VERB/OBJ slot embeddings from M3
   - Architecture: Dual encoder (query + doc) with slot-specific towers
   - Output: Dense retrieval scores with slot explanations
   - **Why**: Learns which slots matter most for different query types
   - **Use**: "Kiu?" queries weight SUBJ higher, "Kion?" weight OBJ

4. **Grammar-Conditioned Reranker** (NEW: 10-20M params)
   - Input: Top-k from M3 cascade + query/doc AST features
   - Architecture: Transformer encoder on [query_ast; doc_ast; grammar_features]
   - Output: Refined ranking scores
   - **Why**: Learns subtle grammatical alignments (tense, case, mood)
   - **Use**: Final reranking stage after M3 deterministic+slot filtering

5. **Contrastive AST Learning** (Training method, not architecture)
   - Positive pairs: Same root with different morphology
   - Hard negatives: Different roots with similar grammar
   - **Why**: Teaches model that "hundo" and "hundojn" are similar (same root)
   - **Use**: Better compositional embeddings (improves Stage 1)

**Most promising for M4:**
- **TreeLSTM Sentence Encoder** (2-5M params)
  - Replaces simple averaging with structure-aware encoding
  - Uses existing AST-to-graph infrastructure
  - Natural extension of EnrichedAST pipeline (Stage 1.5)
  
**Architecture:**
```
M3 Cascade (deterministic → slot)
    ↓
M4 TreeLSTM (structure-aware encoding)
    ↓
M4 AST-Constrained Attention (explainable matching)
    ↓
Final ranking with full AST understanding
```
