# FAISS Optimization Findings for Large-Scale Retrieval

## Problem Context
- FAISSSlotRetriever froze the system when loading slot_full (4.2M docs)
- Root cause: Loading all 4.2M documents into memory during initialization
- Need memory-efficient approach for multi-million document retrieval

## Key FAISS Documentation Findings

### Index Selection for 1M-10M Vectors
**Recommendation**: Use `IVF65536_HNSW32` for 1-10M vectors
- **IVF (Inverted File)**: Clustering-based approach that partitions vectors
- **HNSW**: Graph-based assignment for fast cluster selection
- **Training requirement**: 30×65536 to 256×65536 vectors (manageable for 4.2M)

### Memory Optimization Techniques

1. **Product Quantization (PQ)**:
   - Compresses vectors to reduce memory usage significantly
   - Use `OPQ_D,...,PQ_M` format
   - Trade-off: Some precision loss for major memory savings

2. **Memory-Mapped Indexes**:
   - FAISS supports memory mapping for indexes
   - Load parts of index on-demand rather than all at once
   - Critical for large indexes

3. **Thread Tuning**:
   - **IMPORTANT**: Set OMP threads = physical cores (NOT hyperthreads)
   - Default uses 2× cores (hyperthreads) which is slower
   - Can gain up to 20% speed improvement

4. **Batch Processing**:
   - Load data in batches to avoid memory overflow
   - Essential for datasets that don't fit in RAM

### Known Memory Issues
- **IndexHNSW.add() doubles memory**: When adding vectors, peak memory = 2× dataset size
- **Causes OOM errors** for datasets close to RAM capacity
- **Solution**: Build index incrementally or use disk-based approaches

## Current Implementation Analysis

### FAISSSlotRetriever (PROBLEMATIC)
```python
# Lines 78-89 in slot_retriever_faiss.py
with open(index_file) as f:
    for line in f:
        doc = json.loads(line)
        self.documents.append(doc)  # ❌ LOADS ALL 4.2M DOCS INTO RAM
```

**Problems**:
1. Loads all 4.2M documents into memory (not just embeddings)
2. Uses basic FlatL2 index (no clustering/compression)
3. No memory mapping
4. No thread tuning

### MultiFAISSSlotRetriever (CURRENT APPROACH)
- Uses 3 separate indexes (SUBJ, VERB, OBJ)
- Each index smaller (~1.4M vectors per slot on average)
- Might avoid the freeze issue due to smaller per-index size
- Trade-off: Lower recall (75% vs 85%)

## Recommended Improvements (Future M4)

### For 4.2M Document Index:

1. **Use IVF + PQ compression**:
   ```python
   import faiss
   dim = 128
   nlist = 65536  # 2^16 clusters for 4M docs
   m = 16  # PQ segments
   quantizer = faiss.IndexHNSWFlat(dim, 32)
   index = faiss.IndexIVFPQ(quantizer, dim, nlist, m, 8)
   ```

2. **Enable memory mapping**:
   ```python
   # After building index
   faiss.write_index(index, "index.faiss")
   # Load with mmap
   index = faiss.read_index("index.faiss", faiss.IO_FLAG_MMAP)
   ```

3. **Set thread count**:
   ```python
   import os
   # Set to physical cores (e.g., 8 for M1 Pro)
   os.environ['OMP_NUM_THREADS'] = '8'
   ```

4. **Lazy document loading**:
   - Don't load all documents at init
   - Load on-demand when needed for results
   - Use mmap or SQLite for document storage
