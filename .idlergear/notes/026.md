# MultiFAISS Memory Analysis & Optimization Plan

## CRITICAL FINDING: MultiFAISS Will Exceed 16GB RAM

### Memory Breakdown (4.2M documents)

| Component | Size | Notes |
|-----------|------|-------|
| **Document metadata** | **36.6 GB** | 🔴 KILLER - Lines 90-110 load all into `self.documents` |
| FAISS indexes (3) | 2.1 GB | SUBJ: 863MB, VERB: 888MB, OBJ: 366MB |
| ID mappings | 34 MB | Negligible |
| **TOTAL** | **38.7 GB** | **Exceeds 16GB by 22.7 GB** |

### Root Cause (Same as FAISSSlotRetriever)

**Lines 90-110** in `slot_retriever_multifaiss.py`:
```python
self.documents = []
with open(index_file) as f:
    for line in f:
        doc = json.loads(line)
        doc['slots_np'] = {  # Converts slots to numpy
            k: np.array(v, dtype=np.float32) if v is not None else None
            for k, v in doc['slots'].items()
        }
        self.documents.append(doc)  # ❌ LOADS ALL 4.2M DOCS
```

**Each document**: ~9.3KB (includes text, slots, features, full_embedding, source)
**Total**: 4.2M × 9.3KB = 36.6 GB RAM

## PRIORITIZED OPTIMIZATION RECOMMENDATIONS

### 🔥 P0: Lazy Document Loading (MUST DO)

**Problem**: Loading all 4.2M documents into RAM uses 36.6 GB
**Solution**: Load documents on-demand only when returning results

**Memory Savings**: 36.6 GB → ~50 MB (for top-k results only)

**Implementation**:
```python
class MultiFAISSSlotRetriever:
    def _load_indexes(self):
        # DON'T load documents at init
        # self.documents = []  # ❌ DELETE THIS
        
        # Store only the file path
        self.index_file = self.index_path / "slot_index.jsonl"
        
        # Optional: Build offset index for O(1) lookup
        self._build_offset_index()  
    
    def _build_offset_index(self):
        """Build byte offset index for fast document lookup."""
        self.doc_offsets = []
        with open(self.index_file, 'rb') as f:
            offset = 0
            for line in f:
                self.doc_offsets.append(offset)
                offset += len(line)
    
    def _get_document(self, doc_id: int) -> Dict:
        """Load single document by ID."""
        with open(self.index_file, 'rb') as f:
            f.seek(self.doc_offsets[doc_id])
            line = f.readline()
            doc = json.loads(line)
            # Add numpy slots only for this doc
            doc['slots_np'] = {
                k: np.array(v, dtype=np.float32) if v is not None else None
                for k, v in doc['slots'].items()
            }
            return doc
    
    def search(self, query, top_k=10, ...):
        # ... existing search logic ...
        
        # Stage 3: Only load top-k documents
        for doc_id in candidate_doc_ids:
            doc = self._get_document(doc_id)  # ✅ LOAD ON DEMAND
            # ... scoring logic ...
```

**Trade-offs**:
- ✅ Saves 36.6 GB RAM
- ⚠️ Adds disk I/O latency (~1ms per doc lookup)
- ⚠️ Need to build offset index (one-time ~5 sec cost)

### 🔥 P1: FAISS Memory Mapping (SHOULD DO)

**Problem**: FAISS indexes loaded entirely into RAM (2.1 GB)
**Solution**: Use memory-mapped FAISS indexes

**Memory Savings**: 2.1 GB → ~100 MB (only active pages in RAM)

**Implementation**:
```python
def _load_indexes(self):
    for slot in ['SUBJ', 'VERB', 'OBJ']:
        index_file = multifaiss_dir / f"{slot}.index"
        
        # Load with memory mapping
        index = faiss.read_index(str(index_file), faiss.IO_FLAG_MMAP)
        
        # Set nprobe for IVF indexes
        if hasattr(index, 'nprobe'):
            index.nprobe = 32  # Good balance for 4M docs
        
        self.slot_indexes[slot] = index
```

**Trade-offs**:
- ✅ Saves ~2 GB RAM
- ✅ Minimal performance impact (OS handles paging)
- ✅ Already uses IVF indexes (good!)

### ⚠️ P2: Product Quantization (OPTIONAL)

**Problem**: FAISS indexes still 2.1 GB on disk
**Solution**: Compress with PQ (product quantization)

**Memory Savings**: 2.1 GB → ~500 MB (4x compression)

**Implementation**:
```python
# When building indexes (in _create_multifaiss_indexes)
dim = 128
nlist = int(np.sqrt(embeddings.shape[0]))  # ~1200 for 1.4M
m = 16  # PQ segments (must divide dim evenly)

quantizer = faiss.IndexFlatIP(dim)
index = faiss.IndexIVFPQ(quantizer, dim, nlist, m, 8)  # 8 bits per segment

index.train(embeddings)
index.add(embeddings)
```

**Trade-offs**:
- ✅ 4x compression
- ❌ Recall drop: ~75% → ~70% (may not meet M2 target)
- ❌ Need to rebuild indexes

**Recommendation**: SKIP for now, P0+P1 is sufficient

### 💡 P3: Thread Tuning (FREE WIN)

**Problem**: FAISS uses 2× cores (hyperthreads) by default
**Solution**: Set OMP_NUM_THREADS to physical cores

**Memory Savings**: 0 (but 20% speed gain)

**Implementation**:
```python
import os
# Set before importing faiss
os.environ['OMP_NUM_THREADS'] = '8'  # M1 Pro has 8 P-cores
import faiss
```
