# MemoryMappedSlotRetriever - Deep Performance Analysis

## Current Implementation Analysis

### What It Does Right ✅
1. **mmap for embeddings**: 4 arrays (SUBJ, VERB, OBJ, full) are memory-mapped
2. **Batched processing**: Uses batch_size=1000 to process docs
3. **Lazy embedding access**: Embeddings loaded on-demand from disk

### Critical Problems Found 🔴

## Problem 1: LOADS ALL METADATA INTO RAM (Lines 63-73)

**Same 36.6 GB issue as other retrievers!**

```python
metadata = []
with open(index_file) as f:
    for line in f:
        doc = json.loads(line)
        metadata.append({
            'text': doc['text'],
            'features': doc['features'],
            'source': doc.get('source', {}),
        })
self.metadata = metadata  # ❌ 4.2M × ~9KB = 36.6 GB
```

**Impact**: Freezes on large indexes despite "memory-mapped" name

## Problem 2: ITERATES ALL 4.2M DOCS EVERY QUERY (Lines 244-257)

**This is WHY it's 9x slower than FAISS!**

```python
# Stage 1: Process ALL documents in batches
for batch_start in range(0, self.num_docs, self.batch_size):  # ❌ 4,229 batches!
    batch_scores = self.slot_similarity_batch(...)
    for i, doc_idx in enumerate(range(batch_start, batch_end)):
        # Process each doc
        all_scores.append((slot_score, doc_idx))
```

**Analysis**:
- Processes 4.2M docs in 4,229 batches (1000 docs/batch)
- Each doc: compute slot similarity (lines 154-180)
- **Total operations**: 4.2M × 3 slots × cosine_similarity = **12.6M similarity calculations**
- FAISS processes only ~500 candidates (0.01% of corpus)

**Time breakdown** (estimated):
- 4.2M docs × ~10μs/doc = **42ms** just for iteration
- Feature bonus lookups: 4.2M × metadata access = **~3ms**
- Total: **~45ms** matches observed 44.8ms!

## Problem 3: Non-Vectorized Slot Similarity (Lines 154-180)

**Processes docs one-by-one instead of vectorizing**

```python

    for i in range(batch_size):  # ❌ Python loop per doc
        for slot, weight in self.slot_weights.items():  # ❌ Python loop per slot
            sim = self.cosine_similarity(query_emb, doc_emb)  # ❌ Individual numpy ops
```

**Better approach**: Vectorize across entire batch
```python
# Compute all SUBJ similarities at once
subj_sims = np.dot(self.embeddings['SUBJ'][batch_start:batch_end], query_subj)
```

## Problem 4: Inefficient Cosine Similarity (Lines 129-137)

**Recomputes norms every call**

```python
def cosine_similarity(self, a, b):
    norm_a = np.linalg.norm(a)  # ❌ Recomputed every time
    norm_b = np.linalg.norm(b)  # ❌ Recomputed every time
    return np.dot(a, b) / (norm_a * norm_b)
```

**Better**: Pre-normalize embeddings, use dot product

## OPTIMIZATION RECOMMENDATIONS (Prioritized)

### 🔥 P0: Lazy Metadata Loading (CRITICAL)
**Problem**: Loads 36.6 GB metadata
**Solution**: Same offset index approach as other retrievers
**Savings**: 36.6 GB → ~50 MB

### 🔥 P0: FAISS Pre-filtering Stage (GAME CHANGER)
**Problem**: Processes all 4.2M docs (44.8ms)
**Solution**: Add FAISS pre-filter to 500-1K candidates first
**Architecture**:
```python
Stage 0: FAISS filter (full embeddings) → 500 candidates  # 1-2ms
Stage 1: mmap slot reranking on 500 docs               # 0.5ms  
Stage 2: Full embedding rerank on top 100              # 0.1ms
Total: ~2-3ms (15x faster!)
```

**Why this works**:
- FAISS finds ~500 good candidates in 2ms
- mmap only processes 500 docs instead of 4.2M
- Maintains 90% recall (mmap's strength is reranking, not filtering)

**Expected**: 90% recall, <5ms latency (competitive with FAISS!)

### 🔥 P1: Vectorize Slot Similarity (2-3x speedup)
**Problem**: Python loops per doc/slot
**Solution**: Vectorize across batches
**Code**:
```python
def slot_similarity_vectorized(self, query_slots, indices):
    # Process all docs at once
    scores = np.zeros(len(indices))
    
    for slot, weight in self.slot_weights.items():
        if query_slots[slot] is None:
            continue
        
        # Vectorized dot product for all docs
        doc_embs = self.embeddings[slot][indices]  # (N, 128)
        sims = np.dot(doc_embs, query_slots[slot])  # (N,) - one op!
        
        # Mask NaN slots
        valid = ~np.isnan(doc_embs).any(axis=1)
        scores[valid] += weight * sims[valid]
    
    return scores
```

**Impact**: 3 numpy ops instead of 3 × N × cosine_similarity calls

### 🔥 P1: Pre-normalize Embeddings (20% speedup)
**Problem**: Recomputes norms every cosine_similarity call
**Solution**: Normalize embeddings when creating mmap arrays
**Code**:
```python
# In _create_mmap_arrays():
for slot in ['SUBJ', 'VERB', 'OBJ', 'full']:
    norms = np.linalg.norm(arr, axis=1, keepdims=True)
    norms[norms == 0] = 1  # Avoid division by zero
    arr = arr / norms  # Pre-normalized
    np.save(mmap_dir / f"{slot}.npy", arr)

# Cosine similarity becomes simple dot product:
def cosine_similarity(self, a, b):
    return np.dot(a, b)  # That's it!
```

**Impact**: Saves 2 norm computations per similarity (millions saved)

### ⚠️ P2: Use Float16 for Embeddings (50% memory reduction)
**Problem**: float32 = 4 bytes/value
**Solution**: Use float16 = 2 bytes/value
**Trade-off**: Minimal accuracy loss (<1% recall impact)
**Savings**: 4.1 GB → 2.0 GB for mmap arrays

### ⚠️ P3: Chunk-Based Processing (Better cache locality)
**Problem**: Random access pattern across 4.2M docs
**Solution**: Process documents in contiguous chunks
**Impact**: 5-10% speedup from better CPU cache usage
