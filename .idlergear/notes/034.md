**Created Issues for Alternative Vector Search Libraries**

Added two new retriever implementation tasks to explore FAISS alternatives:

**#217 - HNSWlib-based Retriever** (High Priority)
- Algorithm: Hierarchical Navigable Small World graphs
- Expected: 1.5-2x faster than FAISS, 30-40% less memory
- Target: 85-90% recall at 2-3ms latency
- Advantages: Minimal tuning, "just works" with defaults
- Best for: Speed + simplicity, drop-in FAISS replacement

**#218 - ScaNN-based Retriever** (Medium-Low Priority)
- Algorithm: Anisotropic vector quantization (Google)
- Expected: 5-10% higher recall than FAISS
- Target: 90-95% recall at 3-5ms latency
- Advantages: Optimized for cosine similarity (our use case)
- Best for: When accuracy matters more than speed
- Challenges: Installation complexity, TensorFlow dependency

**Implementation Order**:
1. HNSWlib first (#217) - easier, likely best balance
2. ScaNN second (#218) - only if HNSWlib doesn't meet M3 recall targets (85%+)

**Architecture**: Both follow same pattern as HybridFAISSMmapRetriever:
- Stage 0: Alternative library pre-filtering (4.2M → 500)
- Stage 1: Mmap slot reranking (500 → 100)
- Stage 2: Final ranking (100 → top-k)

**Benchmark Plan**: Compare all three (FAISS vs HNSW vs ScaNN) on same queries to determine production default.
