**ScaNN Slot Retriever - Detailed Design Document**

## Architecture Overview

Three-stage retrieval pipeline matching HybridFAISSMmapRetriever pattern:

**Stage 0: ScaNN Pre-filtering** (~2-3ms)
- 4.2M docs → 500 candidates using anisotropic quantization
- Tree partitioning for coarse search
- Asymmetric hashing for fine-grained scoring

**Stage 1: Mmap Slot Reranking** (~1ms)
- 500 docs → 100 candidates using slot-based scoring
- Reuses existing mmap slot embeddings
- Pre-computed norms for 20% speedup

**Stage 2: Final Ranking** (~0.5ms)
- 100 → top-k results
- Combined score: `slot_weight × slot_score + scann_weight × scann_score`

**Total Expected Latency**: 3-5ms (comparable to FAISS, higher accuracy)

## ScaNN Parameters

Based on Google's 2025 documentation and best practices:

### **Tree Partitioning** (coarse search)
```python
num_leaves = 2000              # Divide data into 2000 clusters
num_leaves_to_search = 100     # Search 100 clusters (balance speed/accuracy)
training_sample_size = 250000  # Samples for tree training
```

**Rationale**:
- num_leaves=2000: Good for ~4M docs (√N heuristic)
- num_leaves_to_search=100: 5% of clusters searched
- training_sample_size=250K: Representative sample

### **Anisotropic Quantization** (fine scoring)
```python
dimensions_per_block = 2                   # Recommended default
anisotropic_quantization_threshold = 0.2   # Balance compression/accuracy
```

**Key Innovation**: Prioritizes preserving parallel components between vectors (most important for inner products) rather than minimizing overall distance.

### **Reordering** (accuracy boost)
```python
reorder_k = 100  # Recompute exact scores for top 100 candidates
```

**Rationale**: Final pass with exact distances for top candidates

### **Distance Metric**
```python
distance_measure = "dot_product"  # For normalized vectors (= cosine)
```

**Important**: ScaNN works best with normalized vectors for cosine similarity

## Memory Optimizations

**P0: Lazy Metadata Loading**
- Build offset index (70 MB) instead of loading all docs (36.6 GB)
- Load metadata on-demand in Stage 1

**P1: ScaNN Compression**
```python
# ScaNN compresses vectors using anisotropic quantization
# Reduces memory footprint while maintaining accuracy
```

**P1: Pre-computed Norms**
- Reuse existing mmap norm arrays from slot indexing
- Avoids recomputing norms during search

**P3: Thread Tuning**
```python
# ScaNN doesn't use OpenMP, but we still optimize environment
# for embedding computation
```

**Expected Memory Usage**:
- ScaNN searcher: ~2-3 GB (similar to FAISS with better compression)
- Mmap slot embeddings: disk-backed (not in RAM)
- Offset index: ~70 MB
- **Total RAM**: ~2.5-3.5 GB (comparable to FAISS)

## Critical Implementation Differences from FAISS/HNSW

### **1. Index Creation (More Complex)**
```python
import scann

# Load and normalize embeddings (REQUIRED for dot_product)
embeddings = np.array(full_embeddings, dtype=np.float32)
norms = np.linalg.norm(embeddings, axis=1, keepdims=True)
normalized_embeddings = embeddings / norms

# Build ScaNN searcher
searcher = scann.scann_ops_pybind.builder(normalized_embeddings, scann_top_n, "dot_product") \
    .tree(
        num_leaves=num_leaves,
        num_leaves_to_search=num_leaves_to_search,
        training_sample_size=training_sample_size
    ) \
    .score_ah(
        dimensions_per_block=dimensions_per_block,
        anisotropic_quantization_threshold=quantization_threshold
    ) \
    .reorder(reorder_k) \
    .build()

# Save to disk (not as clean as HNSW)
searcher.serialize(str(scann_dir))
```

### **2. Search API**
```python
# ScaNN
neighbors, distances = searcher.search(query_vector, final_num_neighbors=k)

# Returns:
# - neighbors: indices (same as HNSW/FAISS)
# - distances: dot products (higher = better for normalized vectors)
```

### **3. Persistence**
```python
# ScaNN (directory-based)
searcher.serialize(str(scann_dir))  # Creates directory with multiple files

# Load
searcher = scann.scann_ops.load_searcher(str(scann_dir))
```

### **4. Distance Metric**
- ScaNN dot_product on normalized vectors = cosine similarity
- Returns **dot products** (higher = better)
- No conversion needed (unlike HNSW distances)

## Expected Performance Targets

**Recall**: 90-95%
- 5-10% higher than FAISS (85%)
- Anisotropic quantization advantage
- Best for cosine similarity

**Latency**: 3-5ms
- ScaNN Stage 0: 2-3ms (vs FAISS 2ms, HNSW 1-2ms)
- Slot rerank: 1ms (same)
- Final ranking: 0.5ms (same)
- Slightly slower than HNSW, but more accurate

**Memory**: 2.5-3.5 GB total
- ScaNN searcher: 2-3 GB (similar to FAISS)
- Comparable to other methods

### **Index Building**
```python
def _build_scann_searcher(self, scann_dir: Path):
    """Build ScaNN searcher from full embeddings."""
    import scann
    
    # Load embeddings from JSONL
    full_embeddings = []
    with open(self.index_file) as f:
        for i, line in enumerate(f):
            doc = json.loads(line)
            full_embeddings.append(doc['full_embedding'])
            
            if (i + 1) % 100000 == 0:
                logger.info(f"Loaded {i+1:,} embeddings...")
    
    # Convert to numpy and normalize (REQUIRED for dot_product)
    embeddings = np.array(full_embeddings, dtype=np.float32)
    norms = np.linalg.norm(embeddings, axis=1, keepdims=True)
    normalized_embeddings = embeddings / norms
    
    logger.info("Building ScaNN searcher...")
    
    # Build searcher
    searcher = scann.scann_ops_pybind.builder(
        normalized_embeddings,
        self.scann_top_n,
        "dot_product"
    ).tree(
        num_leaves=self.scann_num_leaves,
        num_leaves_to_search=self.scann_num_leaves_to_search,
        training_sample_size=min(self.scann_training_sample_size, len(embeddings))
    ).score_ah(
        dimensions_per_block=self.scann_dimensions_per_block,
        anisotropic_quantization_threshold=self.scann_quantization_threshold
    ).reorder(self.scann_reorder_k).build()
    
    # Save to disk
    scann_dir.mkdir(parents=True, exist_ok=True)
    searcher.serialize(str(scann_dir))
    logger.info(f"ScaNN searcher saved: {scann_dir}")
```

## Challenges

1. **Installation Complexity**: ScaNN requires specific TensorFlow version
   - May conflict with other dependencies
   - Python 3.8-3.11 supported
   - No GPU support in Python bindings

2. **Normalization Requirement**: Vectors MUST be normalized for dot_product
   - Extra preprocessing step
   - Must ensure query vectors are also normalized

3. **Persistence Format**: Directory-based (not single file)
   - More complex than HNSW's single .hnsw file
   - Multiple files in scann/ directory

4. **Debugging**: Less mature than FAISS/HNSW
   - Fewer Stack Overflow answers
   - Google-specific documentation

---

## Decision: When to Use ScaNN

**Use ScaNN if**:
- You need >90% recall (accuracy critical)
- M3 milestone requires 85%+ recall
- 3-5ms latency is acceptable
- Installation complexity is manageable

**Use HNSW if**:
- You want simplest implementation
- 2-3ms latency is important
- 85-90% recall is sufficient
- Installation must be hassle-free

**Use FAISS if**:
- You already have FAISS infrastructure
- GPU acceleration is needed
- 85% recall is sufficient
