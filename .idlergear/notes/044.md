## Retrieval Pipeline Analysis - Root Cause Identified

### How Current Retrievers Work

**Two-Stage Architecture:**

**Stage 1: Slot-based Prefiltering** (slot_retriever.py:252-287)
- Scans all documents (49K or 4.2M depending on index)
- Computes `slot_similarity(query_slots, doc_slots)` 
- Slot weights: SUBJ=0.3, VERB=0.4, OBJ=0.3
- Applies feature bonuses (negation=1.1x, tense=1.05x)
- Returns top N candidates (default: 100)

**Stage 2: Full Embedding Reranking** (slot_retriever.py:289-307)
- Takes top 100 candidates from Stage 1
- Computes cosine similarity on full sentence embeddings
- Combines: `final_score = 0.6*slot_score + 0.4*full_emb_sim`
- Returns top K results (default: 10)

### CRITICAL BUGS IDENTIFIED

**BUG #1: Parser Doesn't Extract Proper Noun Subjects**

Test results show:
```
"Kiu fondis Esperanton?" → subjekto: None
"Zamenhof fondis Esperanton." → subjekto: None (!!!)
```

Even statement sentences with proper noun subjects return `subjekto: None`!

**Impact**: 
- Query has slots {VERB: fond, OBJ: esperant} only (missing SUBJ)
- Target sentence ALSO has no SUBJ slot!
- Both are broken, so they "match" on having 2/3 slots
- BUT slot_similarity score is artificially low because SUBJ slot missing reduces coverage

**BUG #2: Slot Overlap is TOO RESTRICTIVE for Questions**

Looking at `slot_similarity()` (slot_retriever.py:148-183):
```python
if query_emb is None and doc_emb is not None:
    # Query missing slot: partial match bonus 0.5
    score += weight * 0.5
```

For "Kiu fondis Esperanton?":
- Query slots: {SUBJ: None, VERB: fond, OBJ: esperant}
- Good answer: {SUBJ: zamenhof, VERB: fond, OBJ: esperant}

Similarity calculation:
- SUBJ: query=None, doc=zamenhof → +0.3 * 0.5 = +0.15 (partial bonus)
- VERB: cosine_sim(fond, fond) → +0.4 * 1.0 = +0.40
- OBJ: cosine_sim(esperant, esperant) → +0.3 * 1.0 = +0.30

Total: (0.15 + 0.40 + 0.30) / 3 = 0.85 / 3 = **0.28 average**

**This is TOO LOW!** Documents with 0.28 slot similarity get buried.

### Is the Prefilter Helping or Hurting?

**HURTING for factual questions**, but for a fixable reason:

1. ✅ **Two-stage design is SOUND** - prefiltering to 100 candidates is efficient
2. ❌ **Slot extraction is BROKEN** - proper nouns not in SUBJ slot  
3. ❌ **Similarity scoring is TOO RESTRICTIVE** - 0.5 partial bonus is too low
4. ❌ **No question word semantics** - "Kiu" should boost person-entity matches

### Evidence from Retriever Code

**Partial match bonus is insufficient** (line 173-174):
```python
elif query_emb is None and doc_emb is not None:
    score += weight * 0.5  # Only 50% credit!
```

Should be closer to 0.8 or 0.9 for questions where missing subject is EXPECTED.

### Specific Problems for "Kiu fondis Esperanton?"

1. **Parser fails**: Both query and target lack SUBJ slot (proper noun bug)
2. **Slot matching weak**: Only 2/3 slots match, score ~0.28
3. **No entity boosting**: "Kiu" (who) doesn't signal to boost person names
4. **Prefilter drops answer**: Score 0.28 ranks below top-100 in large corpus
5. **Stage 2 never sees it**: Reranking can't fix what Stage 1 filtered out

### Recommendation: FIX, DON'T REPLACE

**Don't abandon two-stage design** - it's efficient and correct architecture.

**Fix 3 bugs**:
1. Parser: Extract proper noun subjects (Zamenhof, names)
2. Scoring: Increase partial match bonus 0.5 → 0.8 for questions
3. Entity boosting: "Kiu" → boost docs with person names in SUBJ

**Expected impact**: 8% → 50%+ on factual questions without architectural changes.
