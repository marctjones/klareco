# What Retrievers Return: Data Flow Analysis
## Date: 2026-01-04

## Quick Answer

**Retrievers return**: `List[Tuple[float, Dict]]` where:
- `float` = similarity score (0.0 to 1.0)
- `Dict` = **partial document** with NO full AST, only derived features

## Document Structure Comparison

### Corpus (Full Data with AST)
```json
{
  "text": "La kato dormas.",
  "source": "wikipedia",
  "ast": {
    "tipo": "frazo",
    "subjekto": {"tipo": "vortgrupo", "kerno": {...}},
    "verbo": {"tipo": "vorto", "radiko": "dorm", ...},
    "objekto": null,
    "aliaj": [],
    "fraztipo": "deklaro",
    "negita": false
  },
  "parse_statistics": {"total_words": 3, "success_rate": 1.0}
}
```

### Index (Derived Features, NO AST)
```json
{
  "text": "La kato dormas.",
  "slots": {
    "SUBJ": [0.013, -0.024, ...],  // 64-dim embedding
    "VERB": [0.051, 0.034, ...],
    "OBJ": null
  },
  "features": {
    "negita": false,
    "tempo": "prezenco",
    "fraztipo": "deklaro",
    "modo": "indikativo"
  },
  "full_embedding": [0.032, -0.018, ...],  // 64-dim
  "source": "wikipedia"
}
```

### Retriever Returns (What You Get)
```python
results = retriever.search("Kie estas la kato?", top_k=5)
# Returns: List[Tuple[float, Dict]]

for score, doc in results:
    # score: 0.82 (example)
    # doc: Same structure as Index (NO AST!)
    print(doc.keys())  # ['text', 'slots', 'features', 'full_embedding', 'source']
    print(doc['text'])  # "La kato dormas."
    print(doc['features'])  # {'negita': False, 'tempo': 'prezenco', ...}
    print('ast' in doc)  # FALSE - AST not included!
```

## Data Flow Through Pipeline

```

│ CORPUS (4.2M sentences)                                     │
│ File: data/corpus/unified_corpus.jsonl                      │
│                                                              │

│ ✅ HAS: All morphological annotations                       │
│ ✅ HAS: Parse statistics                                    │
└─────────────────────────────────────────────────────────────┘
                          ↓
                    [INDEXING]
                 (slot_indexer.py)
                          ↓
        Extracts from AST:
        - Slot embeddings (SUBJ/VERB/OBJ)
        - Grammatical features (tense, negation, type)
        - Full sentence embedding
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ INDEX (4.2M entries)                                        │
│ File: data/indexes/slot_full/slot_index.jsonl              │
│                                                              │
│ ❌ NO AST: Dropped during indexing                          │
│ ✅ HAS: Derived embeddings (64-dim vectors)                 │
│ ✅ HAS: Extracted features (negita, tempo, fraztipo, modo)  │
│ ✅ HAS: Text (original Esperanto sentence)                  │

└─────────────────────────────────────────────────────────────┘
                          ↓
                  [RETRIEVAL]
               (slot_retriever.py)
                          ↓
┌─────────────────────────────────────────────────────────────┐
│ RETRIEVER RESULTS                                           │
│ Type: List[Tuple[float, Dict]]                             │
│                                                              │
│ Returns top-k documents from INDEX (not corpus)             │
│ ❌ NO AST in returned documents                             │
│ ✅ HAS: Text, slots, features, embeddings                   │
└─────────────────────────────────────────────────────────────┘
```

## Why AST is Dropped

**Reason**: Memory and speed optimization

**Index size comparison**:
- WITH AST: ~50 GB (full AST structure per sentence)
- WITHOUT AST: ~20 GB (just embeddings + features)

**Loading speed**:
- WITH AST: ~10-15 seconds to load 4.2M documents
- WITHOUT AST: ~2-3 seconds

## Implications

### What You CAN Do with Retriever Results

✅ Get the original text
✅ Access grammatical features (tense, negation, type)
✅ Use slot embeddings for similarity
✅ Display results to user
✅ Extract to answering pipeline

### What You CANNOT Do

❌ Re-parse or modify AST (it's not there!)
❌ Access detailed morphological breakdown
❌ Navigate syntactic structure
❌ See subject/verb/object decomposition

### If You Need Full AST

**Option 1**: Look up in corpus by text
```python
# Retriever returns document
score, doc = results[0]
text = doc['text']

# Look up full entry in corpus
with open('data/corpus/unified_corpus.jsonl') as f:
    for line in f:
        corpus_doc = json.loads(line)
        if corpus_doc['text'] == text:
            ast = corpus_doc['ast']  # NOW you have the full AST
            break
```

**Option 2**: Re-parse on demand
```python
from klareco.parser import parse

score, doc = results[0]
text = doc['text']
ast = parse(text)  # Parse again (slower but works)
```

## Design Rationale

This two-file architecture (corpus + index) follows a common pattern:

**Corpus** = Source of truth, slow, complete
- Like a SQL database with all fields
- Used for training, analysis, debugging

**Index** = Optimized for retrieval, fast, partial
- Like a materialized view with just search fields
- Used for production queries

## Should This Change?

**Trade-offs**:

| Approach | Pros | Cons |
|----------|------|------|
| **Current** (no AST in index) | Fast loading, small index, efficient retrieval | Need corpus lookup for AST |
| **Include AST in index** | One-stop shop, no lookup needed | 2.5x larger index, slower loading |
| **Hybrid** (include minimal AST) | Balance size/speed | Complexity, partial AST may be confusing |

**Recommendation**: Keep current design
- AST rarely needed after retrieval
- Most use cases: just need text + features
- For rare cases needing AST: corpus lookup is acceptable overhead
