# Benefits of Including AST in Index: Analysis
## Date: 2026-01-04

## Current Limitations Without AST

### Problem 1: Lost Structural Information

**Current index** only has:
```json
{
  "slots": {"SUBJ": [embeddings], "VERB": [...], "OBJ": [...]},
  "features": {"negita": false, "tempo": "prezenco"}
}
```

**Missing from index**:
- Subject/object are noun phrases with modifiers (adjectives, determiners)
- Verb phrases with adverbs
- Prepositional phrases and their roles
- Morphological breakdown of each word
- Syntactic relationships between words

**Example**:
```
Query: "Kiu kreas la grandan internacian lingvon?"
Document: "Zamenhof kreis la novan universalan lingvon Esperanto."

Current matching:
- SUBJ: None vs zamenhof (mismatch)
- VERB: kre vs kre (match)
- OBJ: lingv vs lingv (match)
- Modifiers: LOST (grandan, internacian vs novan, universalan)

With AST:
- Could match: "grandan internacian" ≈ "novan universalan" (similar modifiers)
- Could boost: both have adjectives describing the language
```

### Problem 2: Coarse-Grained Matching

**Slot-only matching** misses:
- Modifier similarity (adjectives, adverbs)
- Prepositional phrase matching ("en la domo" vs "ĉe la konstruaĵo")
- Multi-word expression equivalence ("la Unu Ringo" = "Sauron's ring")
- Structural parallelism (similar sentence patterns)

## Potential Benefits of AST in Index

### Benefit 1: Fine-Grained Structural Matching

**With AST, you could**:
```python
def structural_similarity(query_ast, doc_ast):
    """Compare syntactic structures beyond just slot roots."""
    score = 0.0
    
    # Match subject modifiers
    q_subj_mods = extract_modifiers(query_ast['subjekto'])
    d_subj_mods = extract_modifiers(doc_ast['subjekto'])
    score += modifier_similarity(q_subj_mods, d_subj_mods) * 0.1
    
    # Match object modifiers
    q_obj_mods = extract_modifiers(query_ast['objekto'])
    d_obj_mods = extract_modifiers(doc_ast['objekto'])
    score += modifier_similarity(q_obj_mods, d_obj_mods) * 0.1
    
    # Match prepositional phrases
    q_prep = extract_prep_phrases(query_ast['aliaj'])
    d_prep = extract_prep_phrases(doc_ast['aliaj'])
    score += prep_similarity(q_prep, d_prep) * 0.15
    
    # Match verb modifiers (adverbs)
    q_adv = extract_adverbs(query_ast)
    d_adv = extract_adverbs(doc_ast)
    score += adverb_similarity(q_adv, d_adv) * 0.05
    
    return score
```

**Example improvement**:
```
Query: "Kiu rapide venis al la montaro?"
Doc 1: "Frodo rapide venis al la montaro." (exact match, including adverb)
Doc 2: "Frodo venis al la montaro." (no adverb)
Doc 3: "Frodo malrapide iris al la montaro." (opposite adverb)

Without AST:
- All 3 score similarly (just matching veni + montar)

With AST:
- Doc 1: +0.05 (adverb match)
- Doc 2: +0.0 (no adverb)
- Doc 3: -0.05 (opposite adverb)
```

### Benefit 2: Deterministic Question-Answer Type Matching

**With AST, detect structural patterns**:

```python
def qa_structural_match(query_ast, doc_ast):
    """Match question structure to declarative answer structure."""
    
    # "Kiu X?" expects subject in answer
    if query_ast['subjekto']['radiko'] == 'kiu':
        if doc_ast['subjekto'] and doc_ast['subjekto'].get('vortspeco') == 'propra_nomo':
            return 1.2  # Boost: answer has proper noun subject
    
    # "Kion X?" expects specific object
    if query_ast['objekto']['radiko'] == 'ki':
        if doc_ast['objekto'] and has_content_noun(doc_ast['objekto']):
            return 1.2  # Boost: answer has concrete object
    
    # "Kie X?" expects location prepositional phrase
    if 'kie' in extract_words(query_ast):
        doc_preps = extract_prep_phrases(doc_ast)
        if any(is_location_prep(p) for p in doc_preps):
            return 1.3  # Boost: answer has "en...", "ĉe...", "sub...", etc.
    
    return 1.0
```

**Example**:
```
Query: "Kie okazas la batalo?"
Doc 1: "La batalo okazas ĉe Helm's Deep." (has location prep phrase)
Doc 2: "La batalo okazas." (no location)

With AST:
- Doc 1: 1.3x boost (matches "Kie" → location phrase pattern)
- Doc 2: 1.0x (no boost)
```

### Benefit 3: Morphological Feature Matching

**With AST, access word-level morphology**:

```python
def morphology_match(query_ast, doc_ast):
    """Match morphological patterns deterministically."""
    
    # Extract all words from AST
    q_words = extract_all_words(query_ast)
    d_words = extract_all_words(doc_ast)
    
    # Check for morphological parallelism
    q_prefixes = [w['prefiksoj'] for w in q_words]
    d_prefixes = [w['prefiksoj'] for w in d_words]
    
    # Boost if both use same prefixes (mal-, re-, ek-, etc.)
    if set(flatten(q_prefixes)) & set(flatten(d_prefixes)):
        return 1.1
    
    # Boost if both use same suffixes (-ej-, -ist-, -ul-, etc.)
    q_suffixes = [w['sufiksoj'] for w in q_words]
    d_suffixes = [w['sufiksoj'] for w in d_words]
    
    if set(flatten(q_suffixes)) & set(flatten(d_suffixes)):
        return 1.1
    
    return 1.0
```

### Benefit 5: Explainability

**With AST, explain WHY a match scored high**:

```python
def explain_match(query_ast, doc_ast, score):
    """Generate human-readable explanation."""
    explanation = []
    
    # Show slot matches
    if query_ast['verbo']['radiko'] == doc_ast['verbo']['radiko']:
        explanation.append(f"✓ Verb match: {query_ast['verbo']['radiko']}")
    
    # Show modifier matches
    q_mods = extract_modifiers(query_ast['objekto'])
    d_mods = extract_modifiers(doc_ast['objekto'])
    if overlap(q_mods, d_mods):
        explanation.append(f"✓ Object modifiers match: {overlap(q_mods, d_mods)}")
    
    # Show structural patterns
    if is_wh_question(query_ast) and has_answer_pattern(doc_ast):
        explanation.append("✓ Answer structure matches question type")
    
    return "\n".join(explanation)
```

```
Score: 0.87

Explanation:

✓ Object root match: ring
✓ Object modifiers: both have adjectives (grandan ≈ unu)
✓ Answer structure matches "Kiu?" question (has proper noun subject)
```

## Trade-offs

### Costs of Including AST

| Aspect | Current (No AST) | With AST | Increase |
|--------|------------------|----------|----------|
| **Index size** | 20 GB | 50 GB | **+150%** |
| **Index loading** | 2-3 sec | 10-15 sec | **+400%** |
| **Memory usage** | 8 GB (mmap) | 20 GB | **+150%** |
| **Retrieval latency** | 15-20 ms | 25-35 ms | **+66%** |

### Benefits Quantified

| Improvement | Without AST | With AST | Expected Gain |
|-------------|-------------|----------|---------------|
| **Factual Q&A** | 8% → 50% (Bug #1+#2) | 50% → 65% | **+15pp** |
| **Modifier matching** | Not possible | Fine-grained | **New capability** |
| **Q&A pattern matching** | Heuristic only | Structural | **+10-15% accuracy** |
| **Explainability** | Slot-level only | Word/phrase level | **Much better** |
| **Multi-hop prep** | Not feasible | Enables it | **Future unlock** |

## Hybrid Approach: Minimal AST

**Compromise**: Include ONLY essential AST fields, not full structure

```json
{
  "text": "Zamenhof kreis la novan lingvon Esperanto.",
  "slots": {...},
  "features": {...},
  "minimal_ast": {
    "subjekto_words": [{"radiko": "zamenhof", "vortspeco": "propra_nomo"}],
    "verbo_words": [{"radiko": "kre", "tempo": "pasinteco"}],
    "objekto_words": [
      {"radiko": "nov", "vortspeco": "adjektivo"},
      {"radiko": "lingv", "vortspeco": "substantivo"},
      {"radiko": "esperant", "vortspeco": "propra_nomo"}
    ],
    "prep_phrases": [
      {"prep": "de", "object": "la mondo"}
    ]
  }
}
```

**Size comparison**:
- Full AST: +150% (50 GB)
- Minimal AST: +40% (28 GB)
- Current (no AST): 20 GB

## Recommendation

### Phase 1 (Current): No AST - KEEP
**Reasoning**: Fixes Bug #1+#2 should get us to 50-55% accuracy without AST overhead.

### Phase 2 (After Bug fixes validated): Add Minimal AST
**When**: If accuracy plateaus at 50-60%, need more signal
**What**: Include word-level morphology + prep phrases (NOT full tree)
**Expected gain**: +10-15pp accuracy (60% → 70-75%)

### Phase 3 (Future): Full AST for Advanced Features
**When**: Building multi-hop reasoning, complex compositional queries
**What**: Full AST structure in separate enrichment index
**Trade-off**: Accept 2.5x size increase for advanced capabilities

## Implementation Path

```
Now: Bug #1 + Bug #2 fixes → 50-55% accuracy

  ↓
```

## Key Insight

**Don't add AST yet** - fix the bugs first and measure. The current architecture can likely reach 60-65% without AST overhead. Only add AST if we hit a plateau and need fine-grained structural matching to break through.

**The bottleneck right now is bugs (Bug #1, #2, #3), not missing AST access.**
