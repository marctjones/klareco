## Strategic Decision: Prioritize AST-Aware Retrieval Over Embedding Investigation

### Decision Made
Implement AST-aware retrieval (Tasks #49-53) FIRST, before doing embedding investigation (Tasks #40-48).

### Rationale

**AST-Aware Retrieval** solves the problem by **exploiting structure**:
- Uses deterministic pattern matching (no learning needed)
- Handles structural variation (passive, appositive, fragments)
- Question-type specific strategies (WHO/WHEN/WHAT/etc.)
- Multi-strategy robustness (4 parallel approaches)
- **Expected improvement**: 10-12% → 60-70% accuracy (6x)

**Embedding Investigation** only **diagnoses** the problem:
- Tells us IF embeddings are collapsed
- Tells us WHERE they fail (roots vs affixes)
- Recommends fixes (retrain with better loss)
- But doesn't directly improve retrieval

### Decision Point

After implementing AST-aware retrieval (Task #53):

**If accuracy >60%**:
- ✓ Problem solved by exploiting structure
- Keep embeddings as fallback strategy (good enough)
- Skip embedding investigation (Tasks #40-48 stay blocked)
- Focus effort on other priorities

**If accuracy <60%**:
- Unblock embedding investigation (Tasks #40-48)
- Diagnose why embeddings fail
- Improve embeddings to boost fallback strategy
- Target: 80-90% combined (structure + better embeddings)

### Updated Task Priorities

**High Priority** (do now):
- Task #49: Question Classifier
- Task #50: AST Pattern Matcher
- Task #51: Semantic Relation DB (Phase 1)
- Task #52: Entity Recognizer
- Task #53: Multi-Strategy Retriever

**Low Priority / Blocked** (wait for AST-aware results):
- Tasks #40-48: All embedding investigation tasks

### Alignment with Vision

This decision perfectly aligns with Klareco's core thesis:
> "By making grammar, morphology, and linguistic structure 100% programmatic, we can focus all learned capacity on reasoning, not language rules."

We're prioritizing **deterministic processing** (AST patterns) over **learned parameters** (embeddings). This is the right architectural approach.
