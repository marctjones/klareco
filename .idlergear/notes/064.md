## AST-Aware Retrieval Implementation Progress

Completed first 3 components of AST-aware retrieval system (Tasks #49-51):

### 1. Question Type Classifier (Task #49) ✅
**File**: `klareco/rag/question_classifier.py`
**Tests**: `tests/test_question_classifier.py` (22 tests, all passing)

**Features**:
- Deterministic classification using Esperanto correlatives (kiu, kio, kie, kiam, kiel, kial, kiom, ĉu)
- Maps question words to question types (WHO, WHAT, WHERE, WHEN, HOW, WHY, HOW_MANY, BOOLEAN)
- Infers entity types (PERSON, PLACE, TIME, THING, DEFINITION, METHOD, REASON, QUANTITY)
- Detects question focus (which slot: SUBJ/VERB/OBJ)
- Context-based refinement (e.g., "Kio estas X?" → DEFINITION)
- Determines target slots for matching priority

**Key insight**: Uses AST structure to understand question intent, not just keywords.

### 2. AST Pattern Matcher (Task #50) ✅
**File**: `klareco/rag/ast_pattern_matcher.py`
**Tests**: `tests/test_ast_pattern_matcher.py` (16 tests, all passing)

**Features**:
- Direct slot matching (SUBJ/VERB/OBJ)
- Synonym expansion using semantic relations
- Passive voice transformation detection (active ↔ passive)
- Appositive/fragment matching for definitions
- Root extraction with function word filtering
- Passive construction handling ("estis fondita" → extracts "fond")

**Key insight**: Matches structural patterns, not just text similarity. Handles grammatical transformations deterministically.

### Technical Decisions

1. **AST field names**: Use Esperanto names (`subjekto`, `verbo`, `objekto`), not English
2. **Passive voice**: Parser puts passive participle in subject modifiers, not verb
3. **Function word filtering**: Filter pronouns, articles, prepositions, question words from roots
4. **Symmetric relations**: Synonyms and antonyms are bidirectional in database
