## Critical Bug Fix: Vocabulary Size Mismatch in Dual Training

**Problem Found:**
- Linguistic model trained on 11,121 roots (older, smaller corpus)
- Topical data generated with 77,236 roots (full unified corpus)
- Training data uses indices 0-77,235, but linguistic embeddings only have 11,121 entries
- Would cause index out of bounds error during training

**Root Cause:**
The linguistic embedding model was trained earlier on a smaller vocabulary, but the topical training data was generated from the full unified corpus with a much larger vocabulary.

**Solution Implemented:**
Modified `load_linguistic_embeddings()` function to handle vocabulary expansion:

1. **Create model with larger topical vocab size** (77,236 roots)
2. **Map pretrained weights** for roots that exist in both vocabularies
3. **Random initialization** for new roots (66,115 roots)
4. **Freeze linguistic embeddings** during topical training (prevents degradation)

**Coverage:**
- Pretrained: ~11,121 roots (14.4% of total)
- New random init: ~66,115 roots (85.6% of total)

This is acceptable because:
- Topical training will learn new root embeddings
- Linguistic embeddings frozen (won't degrade pretrained quality)
- Most common/important roots likely in the 11K pretrained set

**Alternative Approaches (rejected):**
1. Retrain linguistic model with 77K vocab (time consuming, loses existing quality)
2. Regenerate topical data with only 11K vocab (loses corpus coverage)
3. Use only overlapping roots (loses too much data)

**Files Modified:**
- `scripts/training/train_dual_embeddings.py` - Updated `load_linguistic_embeddings()`
