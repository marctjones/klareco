ASTAwareRetriever Diagnostic Findings (2026-01-07)

## Key Finding: HNSW Pre-filter Rank Gap

**Query**: "Kiu fondis Esperanton?"
**Expected Answer**: "ZAMENHOF, Aŭtoro de la lingvo Esperanto"

**Problem**: The correct answer appears at **rank 413** in HNSW results.
With `prefilter_n=500`, it barely makes the cut. With any filtering, it's lost.

## Root Causes Identified

### 1. Embedding Similarity ≠ Semantic Relevance
- Query ↔ Doc similarity: 0.4172 (mediocre)
- 'fond' ↔ 'aŭtor' similarity: 0.2798 (too low!)
- 'fond' ↔ 'zamenhof' similarity: 0.1184 (very low)

The embeddings don't capture that "Aŭtoro de X" answers "Kiu fondis X?"

### 2. HNSW Ranks "fondis" Documents Higher
Top 10 HNSW results are all about "fondis/fondo" but not about Esperanto:
- "fondinto de Tenrikjo" 
- "li fondis la unuan vapormuelejon"
- "Fondo de Kamenec"

These rank higher because they have VERB slot matching ("fondis") but wrong entities.

### 3. Slot Reranking Can't Recover Missing Candidates
- HNSW pre-filter returns 500-1000 candidates
- If correct doc is at rank 413+, slot reranking starts with wrong pool
- 30% HNSW + 70% slot scoring can't promote doc that's not in pool

## Proposed Solutions

### Quick Fix: Increase prefilter_n
Change `prefilter_n=500` → `prefilter_n=2000` to ensure rank 413 is included.
**Impact**: +latency (~2-4x slower), +recall

### Better Fix: Hybrid Pre-filter Strategy
For WHO/WHEN/WHERE questions:
1. HNSW retrieves top-1000 by embedding similarity
2. **Keyword filter** adds docs containing query entities (Esperanto, Zamenhof)
3. Union both sets before slot reranking

### Best Fix: Train Better Semantic Relations
The embedding model should learn:
- "fond" ↔ "aŭtor" should have similarity > 0.7
- "fond" ↔ "zamenhof" should be higher when in Esperanto context

This requires training data with semantic role equivalences.
