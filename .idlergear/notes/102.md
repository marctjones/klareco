## AST-First Retrieval Architecture (Design Discussion)

**Current Problem**: We're averaging word embeddings into sentence vectors, losing all AST structure.

### What AST-First Means

**Query Processing:**
```
"Kiu kreis Esperanton?" 
  → Parse to AST
  → Extract: {
      query_roots: ["kre", "esperant"],
      query_grammar: {verbo: {tempo: "pasinteco"}},
      question_type: WHO (expects person in response)
    }
```

**Document Index Should Store:**
```json
{
  "doc_id": 12345,
  "text": "Zamenhof kreis Esperanton en 1887",
  "roots": ["zamenhof", "kre", "esperant", "1887"],
  "root_annotations": {
    "zamenhof": {"role": "subjekto", "vortspeco": "propra_nomo"},
    "kre": {"role": "verbo", "tempo": "pasinteco"},
    "esperant": {"role": "objekto", "kazo": "akuzativo"}
  },
  "root_embeddings": {
    "zamenhof": [0.1, 0.2, ...],  // 64d per root
    "kre": [0.3, 0.4, ...],
    "esperant": [0.5, 0.6, ...]
  }
}
```

**Retrieval Strategy:**
1. **Inverted Index by Root**: radiko → [doc_ids] (fast O(1) lookup)
2. **Synonym Expansion**: "kre" → ["kre", "fond", "establ", "iniciat"] via SemanticDB
3. **Set Intersection**: docs containing query roots
4. **Grammatical Scoring**: boost if tempo/kazo/modo match
5. **Embedding Similarity**: for roots not in inverted index, use embedding similarity

### Benefits
- No embedding collision (each root stored separately)
- Grammatical features preserved and searchable
- Synonym expansion happens at query time, not index time
- Can answer "find all docs where X is the subject" (structural queries)
- Explainable: "matched because doc contains 'fond' (synonym of 'kre') as verb"

### Implementation Path
1. Build inverted index: `root → [(doc_id, role, grammar_features), ...]`
2. Store per-root embeddings (not averaged)
3. Query by root matching + embedding fallback for unknown roots
4. Grammatical filtering as post-retrieval boost

### Relation to Existing Code
- SemanticRelationDB already has synonym/antonym/hypernym mappings
- EntityRecognizer extracts roots from AST
- SemanticPipeline provides 64d root embeddings
- Just need to reorganize the index structure
