## Performance Optimization Journey

### Approaches Tested

| Approach | Speed | Total Time | Status |
|----------|-------|------------|--------|
| v1: Individual UPDATEs with SKIP/LIMIT | 200 nodes/sec | ~100 min | ❌ Too slow |
| v2: Batched UNWIND | 55 nodes/sec | ~6 hours | ❌ **3.6x slower!** |
| v3: Transaction batching | 143 nodes/sec | ~145 min | ❌ Didn't work |
| **v4: COPY FROM + JOIN** | **~6700 nodes/sec** | **~2 min** | ✅ **33x faster!** |

### Final Solution: COPY FROM Method

**Strategy:**
1. Fetch all 1.2M radiko strings (102 seconds)
2. Classify in Python with dict lookups (1.7 seconds)
3. Write to CSV (1.1 seconds)
4. COPY FROM into temp table (1.4 seconds - Kuzu's fastest bulk operation)
5. **Single UPDATE with JOIN** (5.2 seconds - **ONE checkpoint instead of 1.2M!**)
6. Drop temp table

**Total: 111.8 seconds for Radiko classification**

**Key Insight:** The bottleneck was checkpoint overhead (1.2M individual transactions). Using COPY FROM + single JOIN reduced this to ONE transaction.

## Lessons Learned

1. **SKIP/LIMIT with large offsets is extremely slow** - Use cursors, ID ranges, or fetch-all instead
2. **Kuzu's COPY FROM is the fastest bulk operation** - Use it for any bulk data loading
3. **Single UPDATE with JOIN beats 1M individual UPDATEs** - Reduces checkpoints dramatically
4. **Simple queries often beat "clever" optimizations** - Individual PRIMARY KEY lookups beat complex UNWIND
5. **String manipulation overhead can dominate** - The "fast" UNWIND version was 3.6x slower due to Python string building
6. **Memory is cheap for structured data** - 1.2M strings = ~100MB (no problem on modern systems)
7. **Measure, don't guess** - Performance bottlenecks were not where expected
